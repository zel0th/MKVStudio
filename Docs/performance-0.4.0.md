# Нагрузка MKVStudio 0.4.0

20 октября 2026. Mac с Apple M4, 10 ядер, 24 ГиБ памяти, macOS 27.0.1. Release-сборка, утилиты 102.0. CPU указан относительно одного ядра: 100% означает одно полностью занятое ядро. RSS — резидентная память, а не объём всех выделений.

## Настоящее приложение SwiftUI

Измерение `Scripts/sample-ui.py`, интервал 50 мс, счётчики CPU/RSS процесса приложения и его непосредственных дочерних процессов. Использован синтетический MKV около 1 ГиБ с PCM, PNG-обложкой и XML-вложением. Пользовательские медиа не использовались.

Проверены импорт, редактирование стандартных тегов, просмотр PNG/XML и встроенных тегов через Quick Look, сборка, очистка источников, перезапуск. После удаления ненужной копии XML из состояния приложения повторены запуск, импорт, редактор, сборка и очистка.

| Сценарий окончательной сборки | Длительность | Средний CPU приложения | Пиковая RSS приложения |
|---|---:|---:|---:|
| Пустое окно, без действий | 19,86 с | 0,015% | 138,83 МиБ |
| Импорт и работа в редакторе тегов | 32,22 с | 5,55% | 154,56 МиБ |
| Интервал запуска и завершения сборки с тегами | 23,04 с | 1,78% | 161,25 МиБ |
| Пустое окно после очистки | 53,69 с | 0,26% | 189,19 МиБ |

Интервал сборки включает время до/после выполнения и не является CPU только активной обработки. Для активной обработки отдельно приведены результаты движка ниже. В предварительной UI-проверке с Quick Look пик RSS приложения составил 204,44 МиБ. Сам процесс во время просмотра использовал в среднем 2,25% одного ядра за 68,38 с; это включает действия открытия и закрытия. Внешние системные службы Quick Look, WindowServer и прочие процессы macOS не входят в RSS приложения. Числа не означают общую нагрузку всех процессов системы.

## Логика очереди и консольные утилиты

`Scripts/benchmark.py`: настоящий AppState без SwiftUI, синтетический PCM-файл 1 ГиБ, 12 последовательных операций — по четыре обычных сборки, склейки двух входов и разбиения по 256 МиБ. Каждое задание дополнительно записывает TITLE, DIRECTOR, DATE_RELEASED и RECORDING_LOCATION через mkvextract/mkvpropedit. Все 12 заданий завершились успешно, после каждого результат удалялся.

[Полные результаты 12 заданий](queue-benchmark-0.4.0.jsonl). Короткий тест не доказывает отсутствие всех возможных утечек, но не показывает неограниченного роста памяти очереди на этой нагрузке.

## Ограничение нагрузки в реализации

- Медиафайлы обрабатываются потоково внешними утилитами и не читаются целиком в память приложения.
- Теги читаются по запросу; разбираются вне главного потока. В состоянии интерфейса остаются только значения полей, без дополнительной копии исходного XML.
- Разбор XML ограничен 2 МиБ, глубиной 32 и числом узлов 20 000; внешние сущности не загружаются.
- Одновременно готовится одно вложение до 50 МиБ. Извлечение идёт в отдельном процессе, отображение поручено нативному Quick Look. Временная папка удаляется после закрытия, очистки источников или выхода.
- Журнал и очередь событий ограничены; обновления прогресса объединяются с интервалом 200 мс. Теги применяются последовательно к частям разбиения.
- Повторно прошли [22 интеграционные проверки](integration-0.4.0.txt); результат из UI отдельно проверен повторным чтением тегов консольными утилитами.

Сырые измерения интерфейса сохранены локально в `build/verification/`; это временные материалы проверки, не часть исходного репозитория.
